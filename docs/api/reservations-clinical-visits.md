# Reservations and clinical visits

> [não verificado] routes, roles, rule names, settings and the confirmed rules below were checked against the code; the read-scope rules and the lock/applock sequences were not re-traced statement by statement.

## Reservations and clinical visits

Instants (`startAt`, `endAt`, `confirmedAt`, `cancelledAt`, `startedAt`, `endedAt`, `voidedAt`) are ISO-8601 with an explicit offset or `Z`; values without an offset are rejected (400). They are stored in UTC and returned as UTC ISO strings. `createdAt`/`updatedAt` come from the SQL Server default `SYSDATETIME()` (server clock; see [../database.md](../database.md#conventions)). Business hours (Mon-Fri 07:00-20:00, one clinic day) are evaluated in Europe/Lisbon.

| Route | Access | Rule |
| --- | --- | --- |
| GET /api/vetcare/reservations | authenticated roles | filters status, clientId, employeeId, createdBy, animalId, from, to (startAt), skip/take (`createdBy` only narrows the scope; non-admins may only filter by their own id, any other id returns an empty page); scoped: ADMIN all, active employee assigned to them, client own, and every reservation of animals the caller is an active tutor of |
| GET /api/vetcare/reservations/:id, GET /api/vetcare/reservations/:id/history | same scope (403 otherwise) | history is chronological; non-admins see `changedBy` only when it is themselves (`changedBySelf`), and in `CLIENT_CHANGED` events `oldData.clientId`/`newData.clientId` only when it is their own id (null otherwise) |
| POST /api/vetcare/reservations | ADMIN, EMPLOYEE, CLIENT | always PENDING; `createdBy` = caller (never accepted in the body: 400); `serviceId` required (404 unknown, 409 `SERVICE_INACTIVE`); `endAt` = startAt + service `durationMinutes` (optional in the body: the same value is accepted from anyone, a different one only from ADMIN, 400 `END_AT_MISMATCH` otherwise); `employeeId` (pre-assignment, CREATED + EMPLOYEE_ASSIGNED) only for ADMIN (403 otherwise) and qualified for the service (400 `EMPLOYEE_NOT_QUALIFIED`), like PATCH /employee |
| PATCH /api/vetcare/reservations/:id/employee | ADMIN | PENDING only; bookable employee qualified for the reservation's service (400 `EMPLOYEE_NOT_QUALIFIED`; not checked when `serviceId` is null); EMPLOYEE_ASSIGNED or EMPLOYEE_CHANGED; never confirms |
| POST /api/vetcare/reservations/:id/confirm | ADMIN | PENDING with employee (still qualified for the service), future, not blocked, no overlap, animal not deleted (409 `ANIMAL_UNAVAILABLE`), client active (409 `CLIENT_INACTIVE`), no clinical visit (VOIDED included; 409 `RESERVATION_HAS_VISIT`); sets confirmedAt |
| POST /api/vetcare/reservations/:id/reschedule | ADMIN | PENDING/CONFIRMED without any clinical visit (VOIDED included; 409 `RESERVATION_HAS_VISIT`); optional `endAt` (default: the reservation's own duration, end - start); assigned employee still qualified; animal not deleted and client active (409 as confirm); CONFIRMED returns to PENDING (confirmedAt cleared); RESCHEDULED with old/new |
| POST /api/vetcare/reservations/:id/cancel | ADMIN or the reservation's client | PENDING/CONFIRMED without an IN_PROGRESS/COMPLETED visit; the client only before startAt (409 `CANCEL_AFTER_START`), ADMIN at any time; sets cancelledAt |
| POST /api/vetcare/reservations/:id/no-show | ADMIN | CONFIRMED, without an IN_PROGRESS/COMPLETED visit, after startAt + `RESERVATION_NO_SHOW_TOLERANCE_MINUTES` |
| GET /api/vetcare/clinical-visits, GET /api/vetcare/clinical-visits/:id | authenticated roles | clinical access below |
| POST /api/vetcare/clinical-visits | ADMIN, EMPLOYEE | from a CONFIRMED reservation without any visit (VOIDED included; same animal), started only by the employee assigned to the reservation or ADMIN; or without reservation (animalId). Responsible = caller (reservation's employee by default), or any active employee chosen by ADMIN. From a reservation with a service, that responsible employee must hold the service (400 `EMPLOYEE_NOT_QUALIFIED`); walk-ins and reservations without `service_id` are not checked. At most one IN_PROGRESS visit per animal (409 IN_USE, message only; find the visit with GET /api/vetcare/clinical-visits?animalId=...&status=IN_PROGRESS); a concurrent start that violates `uq_vc_clinical_visits_reservation_id` gets the same 409 (`RESERVATION_HAS_VISIT`) |
| PATCH /api/vetcare/clinical-visits/:id | ADMIN or responsible | IN_PROGRESS only (clinicalNotes, description) |
| POST /api/vetcare/clinical-visits/:id/complete | ADMIN or responsible | IN_PROGRESS -> COMPLETED (endedAt, completedBy = caller's account); its reservation CONFIRMED -> COMPLETED + COMPLETED event |
| POST /api/vetcare/clinical-visits/:id/void | ADMIN | IN_PROGRESS -> VOIDED with mandatory reason (voidedAt never before startedAt, voidedBy) |

Authorship: `vc_reservations.created_by` (migration `1795521600000`) is the account that created the reservation, distinct from `client_id` (the responsible tutor): a client booking their own animal is both; staff or an administrator booking for a client is the author only. POST always writes the authenticated caller; no later operation (assign, confirm, reschedule, cancel, no-show, visit completion, `CLIENT_CHANGED` tutor moves) changes it. NULL means system/unknown (reservations created before the migration without a `CREATED` event). It equals `changedBy` of the `CREATED` history event (at most one per reservation, filtered unique index); the history snapshots do not repeat it. Responses carry `createdBy` and `createdBySelf` with the `changedBy` rule of history events: administrators see `createdBy`; others see it only when it is their own id (null otherwise, so the id of the employee who booked for a client is not exposed) and every caller gets `createdBySelf`; the creator account is never serialized to non-administrators. Authorship grants no access: an employee who books for a client sees the reservation afterwards only when it is assigned to them (the read rules above are unchanged).

States: PENDING -> CONFIRMED | CANCELLED; CONFIRMED -> COMPLETED | CANCELLED | NO_SHOW (409 otherwise). COMPLETED is reachable only through visit completion. Every change and its history event share one transaction; the reservation row is read with UPDLOCK. Confirmation, assignment, reschedule and creation with an employee take the clinic closures applock (`vc_blocked_times:global`, Shared) and then `sp_getapplock` on `vc_reservations:employee:<employeeId>` (Exclusive, Transaction owner, 5 s) before checking the employee's schedule, clinic closures and the employee's blocks, and overlaps: timeout/deadlock return 409, other failures 503. Overlap counts only CONFIRMED reservations of the employee, widened by `RESERVATION_BUFFER_MINUTES`. Creation and reschedule without an employee only check clinic closures (see "Employee schedules, blocked times and availability"). Notifications are sent after commit (`notificationStatus`); user values in email HTML are escaped. Cancel, no-show and visit completion only free time and therefore run without the applock (safe: they can never create an overlap). Rescheduling a PENDING reservation whose employee is no longer bookable fails (400): reassign the employee first (PATCH /employee). Any clinical visit, VOIDED included, blocks confirm and reschedule (409 `RESERVATION_HAS_VISIT`, message "The reservation already has a clinical visit (voided visits included); it cannot be confirmed or rescheduled"; before, a reservation with an IN_PROGRESS visit got the VISIT_STARTED message, "The reservation has an active clinical visit; ..."). Only IN_PROGRESS and COMPLETED visits block cancel and no-show, so a VOIDED visit does not. A reservation never gets a second visit: `uq_vc_clinical_visits_reservation_id` also covers VOIDED rows, and a concurrent start that violates it returns 409 with the message "The reservation already has a clinical visit". SQL deadlock victims (1205) and lock timeouts (1222) return 409.

Clinical access (no RBAC): ADMIN sees everything; an employee with an active profile sees visits they are responsible for and visits of animals with a reservation assigned to them in CONFIRMED, COMPLETED or NO_SHOW (a PENDING assignment grants nothing); every active tutor (primary or secondary) of the animal sees its visits without `clinicalNotes`/`voidReason`. `voidedBy` and `completedBy` are shown only to ADMIN. Employees in responses are `{ id (vc_employees.id), name, profilePictureUrl }` (ADMIN also `userId` and the account).

`/api/vetcare/animal-measurements` (writes restricted to staff, see "Measurement types and observations") accepts an optional immutable `clinicalVisitId` (also a list filter). Linking requires an IN_PROGRESS visit of the same animal and clinical access; the save runs under the visit lock. Measurements of a visit can be edited only while it is IN_PROGRESS and are never deleted (409).

`RESERVATION_NO_SHOW_TOLERANCE_MINUTES` and `RESERVATION_BUFFER_MINUTES` accept only integers 0..2147483647 through `/api/vetcare/system-settings` (400 otherwise); an invalid stored value fails closed (500). The former routes `/api/vetcare/reservation/*` (create, update-status, all, client, employee, confirm-pending, confirm-rescheduled, reject-rescheduled, :employeeId/:date, PUT/DELETE :id) were removed.

Not implemented: an audit trail of `clinical_notes` changes while a visit is IN_PROGRESS (only the final state and the void metadata are kept).

## Confirmed rules

- `serviceId` is required on POST /api/vetcare/reservations: `@IsUUID()` without `@IsOptional()` (`src/app/reservation/dto/create-reservation.dto.ts`), so an absent or malformed value is 400 (validation); a well-formed id of an unknown service is 404 `SERVICE_NOT_FOUND` (`src/app/reservation/reservation.business.service.ts`, service lookup with `SHARED_LOCK`).
- An employee who does not hold the reservation's service is 400 (`INVALID_VALUE`, internal code `EMPLOYEE_NOT_QUALIFIED`) in `requireBookableEmployee` (creation with an employee, PATCH /employee, confirm, reschedule); an unknown service is 404 (`NOT_FOUND`).
- `GET /api/vetcare/reservations?createdBy=<other id>` from a non-administrator returns an empty page, not 403 (`ReservationBusinessService` list: `if (query.createdBy && !actor.isAdmin && !sameId(query.createdBy, actor.id)) return [];`).

## Decisions

- Qualification when starting a visit (formerly pending): decided and implemented. POST /api/vetcare/clinical-visits from a reservation with a service checks `isQualifiedForService` for the responsible employee and answers 400 `EMPLOYEE_NOT_QUALIFIED` (`src/app/clinical-visits/clinical-visit.business.service.ts`, `start()`); walk-ins and reservations without `service_id` are not checked.
