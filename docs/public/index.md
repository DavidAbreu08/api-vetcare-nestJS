# VetCare API - consumer contract

What API consumers (for example the `vetcare-angular` frontend) may rely on. Internal implementation lives outside `docs/public/` and must not be read by consumers.

## Contract source

- Source of truth for endpoints: [openapi.json](openapi.json) (OpenAPI 3, 98 operations), generated by NestJS Swagger with `npm run docs:openapi` (no database needed). The same document is served at `/docs-json` (UI at `/docs`) while the server runs (`npm run start:dev`, port 3000); Swagger is disabled there when `SWAGGER_ENABLED=false` or, without that variable, when `NODE_ENV=production` (`src/swagger.ts`).
- Contract version (`info.version`): `0.0.1` (`src/swagger.ts`).

## Base URL and authentication

- Every operation is under the global prefix `/api/vetcare` (`src/api-routing.ts`). There are no aliases for the old `/api` prefix.
- Sign in with `POST /api/vetcare/auth/login`; send the returned JWT as `Authorization: Bearer <token>` (security scheme `bearer` in OpenAPI).
- Public operations: `POST /api/vetcare/auth/login`, `POST /api/vetcare/auth/forgot-password` and `PUT /api/vetcare/auth/reset-password` (both rate limited), `POST /api/vetcare/users`, `GET /api/vetcare/clinic/hours`. Every other operation requires the JWT; role, ownership and tutorship checks are applied on top.

## Conventions

- Identifier path parameters are UUIDs (invalid values return 400). Unknown body or query fields are rejected with 400.
- Base collections accept `skip` (default 0) and `take` (default 50, maximum 100).
- PATCH is a partial update; PUT is used only for whole-list replacements (`/users/:id/roles`, `/employees/:id/services`, `/employees/:id/schedules`) and confirmation/password-reset actions.
- Status codes: 201 for creation, 200 for completed actions (including login, password change and primary tutor transfer), 202 for `forgot-password` (background work), 204 only when there is no body.

## Response envelope

```ts
interface HttpResponse<T = unknown> {
  status: HttpStatus;          // equals the HTTP status
  friendlyMessage: string;     // public message, in English
  success: boolean;
  result: T | null;            // operation data; null on errors
  errorMetadata?: ErrorMetadata; // only on errors
}
```

HEAD, 204, 304 and file responses have no envelope. Validation messages are joined with `; ` in `friendlyMessage`; there is no structured field-error map.

## Common errors

`errorMetadata` is one of these global categories (`src/app/core/enums/error-metadata.enum.ts`):

| errorMetadata | HTTP |
| --- | --- |
| `INVALID_VALUE`, `VALIDATION_ERROR`, `HTTP_ERROR` | 400 |
| `UNAUTHORIZED` | 401 |
| `FORBIDDEN` | 403 |
| `NOT_FOUND` | 404 |
| `ALREADY_EXISTS`, `IN_USE`, `CONFLICT` | 409 |
| `TOO_MANY_REQUESTS` | 429 |
| `INTERNAL_ERROR` | 500 |
| `SERVICE_UNAVAILABLE` | 503 |

Ids referenced in a request body: a required id absent from the body (or not a UUID) is 400 `VALIDATION_ERROR`; a well-formed id with no matching entry is 404 and an existing but inactive entry newly referenced is 409 (hidden inactive entries answer 404). Concurrency conflicts (deadlock, lock timeout) answer 409 with a "retry" message.

## Changes

Incompatible changes for consumers:

- `GET /api/vetcare/users/check-email` was removed (commit `8bfcc2b`); registration (`POST /api/vetcare/users`) still answers 409 `ALREADY_EXISTS` for a duplicate email or NIF.
- Deprecated route aliases, the old `/api` prefix and duplicate PUT partial-update handlers are not registered.
- Response envelope migration:
  - Data previously returned at the root now appears in `result`: for example, `response.token` becomes `response.result.token`.
  - Public `message` becomes `friendlyMessage`; `statusCode` becomes `status`.
  - Former domain-specific codes (`EMPLOYEE_UNAVAILABLE`, `INVALID_TRANSITION`, etc.) become generic categories, usually `CONFLICT` or `INVALID_VALUE`.
  - Extra conflict details (IDs, counts and other fields) are excluded from error responses. They can remain available internally for domain rules and diagnosis, but the filter emits only the agreed contract.
  - Swagger documents the global envelope.
