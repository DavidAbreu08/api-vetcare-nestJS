## Não verificável sem BD real

- N1. Semântica dos dados legados: `start`/`end` de `vc_blocked_times` são instantes UTC (M3:18 e doc :268, "UTC instants written by clinicDateTime"). O escritor histórico não está no working tree; `clinicDateTime` existe em `src/app/availability/availability-policy.ts`, `src/app/blocked-times/time-utils.service.ts` e `src/app/employee-schedules/employee-schedule-policy.ts`, mas só como código atual. Se não forem UTC, todos os bloqueios legados ficam deslocados, sem erro de SQL. Impacto Crítico se falso. Verificar no histórico git (`git log -S clinicDateTime`) ou em dados reais.
- N2. Pré-condições de dados (51074, 51093, 51102, 51103) e a contagem de reservas sem autor (M1:105-108) dependem dos dados reais.
- N3. Execução real dos batches: CHECK com COLLATE (M2:8, :70), `DEFAULT NEWSEQUENTIALID()` em CREATE TABLE (M2:60; M3:65), e ALTER COLUMN NOT NULL→NULL (M3:111-114) sem dependências ocultas (índices ou constraints criados fora das migrations). Exige inspeção de `sys.*` na BD.
- N4. `UPDATE()` devolve TRUE para todas as colunas num INSERT (M4:102-103): comportamento documentado do SQL Server, não testado. Se falhar, o trigger de reservas retorna cedo em INSERT, o que só afeta INSERT com status COMPLETED (a app nunca o faz).
- N5. Concorrência sob RCSI: as leituras cruzadas com READCOMMITTEDLOCK em sentidos opostos (M4:89 lê reservas no INSERT de visita; M4:106 e :111 leem visitas no UPDATE de reserva) podem dar deadlock (1205). Não testado. A app bloqueia a reserva com UPDLOCK (`reservation.entity.ts:11`), o que pode mitigar.
- N6. Nomes de DEFAULT (`df_*`) não declarados nas entidades (M2:60, :65, :66; M3:65, :72, :73, :95). O TypeORM gera nomes próprios. Se o schema:log comparar nomes, propõe recriação. Só verificável com schema:log contra a BD.
- N7. Índices: comparação do filtro `where` de `uq_vc_reservation_history_created` (`reservation-history.entity.ts:11`) com o `filter_definition` do SQL Server, e colunas INCLUDE (M3:84-85, :122-123) que não estão declaradas nas entidades. Pode haver diff no schema:log.
- N8. Duração do TABLOCKX durante os backfills (M1:66-71; M3:99-101) em tabelas grandes: não medida.
- N9. Mapeamento real de erros (Msg 3616 e precedingErrors) com um erro verdadeiro do driver mssql: o código foi lido, não testado.
- N10. Saída real do schema:log: os achados 1 e 2 são inferidos do código do TypeORM 0.3.20 (RdbmsSchemaBuilder.js), não de uma execução.
